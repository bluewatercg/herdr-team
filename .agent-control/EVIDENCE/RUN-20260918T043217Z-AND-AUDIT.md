## Source trace

### Original JPEG and SHA-256

- `NativeCameraManager.captureRawJpeg()` requires `ImageFormat.JPEG`, copies `image.planes[0].buffer` once, and only reads EXIF. No Bitmap decode, re-encode, PNG conversion, or App-side ROI crop is on this path.
- `LfaViewModel.handleRawCapturedBytes()` rejects stale/duplicate callbacks and passes the same byte array to persistence.
- `JournaledArtifactStore.persistFirstGenerationBytes()` validates the JPEG signature, computes SHA-256 over the received bytes, rejects a conflicting Bundle SHA, writes `.img_part` and `.journal_part` with `fsync`, then atomically renames. Existing attempt artifacts are not overwritten.
- `verifyUploadCandidate()` rechecks allowed queue state, DB/journal/Bundle identity, canonical path, file size, and file SHA before upload. Integrity mismatch is refused, not converted to zero or success.
- `ReconciliationEngine` quarantines partial artifacts, rebuilds only from hash-consistent evidence, retains unanchored originals, and changes interrupted `UPLOADING` to `UPLOADED_UNCONFIRMED` for lookup rather than blind repost.

### Bundle, multipart, recovery, and result binding

- `LfaViewModel.onShutterTriggered()` creates Bundle schema `1.5` with independent session, attempt, and bundle UUIDs. Persistence supplies `original_sha256` from original bytes.
- Public metadata is frozen as `dhea-capture/2.0`, binds the three IDs, JPEG media type/SHA, capture/application/lot/camera evidence, and fixed `DHEA` / `SALIVA` / `COMPETITIVE_LFA` assay context.
- `DheaClient.submit()` performs GET first on `/api/v2/lfa/measurements/{capture_bundle_id}`. Only `NOT_FOUND` permits POST `/api/v2/lfa/measure`.
- POST uses `Idempotency-Key: capture_bundle_id`, `metadata` / `metadata.json`, and `image` / `original.jpg`. The JPEG RequestBody streams the file and recomputes size and SHA while writing.
- TLS origin is restricted to HTTPS without userinfo/path/query/fragment; redirects and automatic retry are disabled; Authorization is bearer-token based; response bodies are limited to 256 KiB and strict UTF-8/JSON.
- `DheaJson.result()` requires `dhea-result/2.0`; exact capture bundle/attempt/session, original SHA, and metadata SHA; UUID analysis ID; exact research markers; and consistent measurement/quantification nullability.
- Terminal replay cannot change business status, analysis ID, research profile, measurement bundle, nominal concentration, or source artifact hashes.
- `LfaViewModel.acceptPersistedResult()` persists only verified results. `completed` and `rejected` become `CONFIRMED`; processing remains unconfirmed; failures retain retry semantics. A historical confirmed row cannot become an upload candidate.

### Preview-to-JPEG coordinates

- CameraX Preview, ImageCapture, and ImageAnalysis share one `UseCaseGroup.ViewPort`.
- `CoordinateTransform` maps the PreviewView guide to captured `ImageProxy` coordinates. Evidence records Preview/JPEG dimensions, rotation, EXIF, scale type, camera, zoom, preview/image regions, mapping status, and a 9-point round trip.
- Bundle validation requires exactly nine evaluated points and at most 2 px round-trip error for `MAPPED`; unavailable transforms and mirrored EXIF remain explicitly non-evaluable.
- `PreviewGuidanceAnalyzer` maps only the guide into analysis coordinates, handles 0/90/180/270 rotations and crop/buffer layout, and never gates the manual shutter.

### Result and refusal display

- `ResearchResultPanel` distinguishes completed, rejected, processing, and failed; displays wire code and bounded recovery guidance; and renders absent T, C, T/C, and concentration as unknown/not calculable.
- The research markers remain visible: `RESEARCH_CANDIDATE`, `MVP_RESEARCH_RESULT_ONLY`, `NOT_IMPLEMENTATION_BASELINE`, `formal_reporting_allowed=false`.
- Optional laboratory comparison accepts a finite non-negative nominal only for a user-asserted standard; unknown samples keep nominal concentration null.
- Queue UI requires lookup after an unknown receipt and allows same-original retry only after a server not-found result.
